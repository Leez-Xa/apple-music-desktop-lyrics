## 确认的问题与修复

Windows PowerShell 的 Math.Max(0, 0.35) 会选择整数重载并返回 0，而 Math.Max(0.0, 0.35) 才返回 0.35。旧代码的年龄补偿和位置钳制都存在这种隐式整秒转换。40 条本机测量中观察到约 0.494 秒的最大舍入误差；该问题会产生前后误差，不能把它解释为固定 1–2 秒的唯一来源。

新代码统一使用 double 运算，保留真实小数秒。媒体位置读取等待从 500 ms 缩短到 150 ms，窗口换行检查从 100 ms 缩短到 50 ms。媒体元数据短期缓存 500 ms；歌曲起点、时长或来源变化会提前刷新，避免每次时间轴读取都调用元数据异步接口。

默认校正为 0，没有硬编码“全部歌词提前 1 秒”。底部“校时”菜单支持当前歌曲提前或延后，每步 0.2 秒，范围 ±5 秒；Ctrl+左箭头提前，Ctrl+右箭头延后，Ctrl+0 恢复默认。调整只改变展示定位，不改歌词文件、不改播放位置、不影响其他歌曲；在当前进程内记忆，退出后恢复默认。

## 实际限制

LRCLIB 与 Apple Music 可能采用不同版本和标注时间，且此工具目前没有直接读取原生当前句。程序计算精度和采样链路改善，不等于已经证明两套歌词在每首歌上零偏差。若仍有固定延迟，可对该曲使用“提前”校时；不能用无证据的全局补偿冒充精确原生同步。
