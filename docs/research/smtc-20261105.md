## 集成接口

```python
from amlyrics.smtc_bridge import SmtcBridgeMonitor, inspect_sessions

probe = inspect_sessions(timeout=10.0)  # 一次只读诊断；返回 dict
monitor = SmtcBridgeMonitor()           # PlaybackMonitor 子类
monitor.subscribe(on_playback_state)   # 回调接收现有 PlaybackState
try:
    monitor.start()                     # 不等待 WinRT 查询或第一帧
    # 应用继续其既有事件循环；回调在监控后台线程执行。
finally:
    monitor.stop()                      # terminate + wait；必要时 kill + wait
```

- `capability`：`supported / implementation / reason`。`supported=True` 代表 Windows、本机 Windows PowerShell 及脚本文件这些前提具备，不代表当前一定有 Apple 会话或 WinRT 查询必然成功。原生启动错误由 `last_error` 报告。
- `state`：最近一次发布的现有 `PlaybackState`；没有新增公共契约字段。
- `last_snapshot`：最近一帧内部协议 dict；初始为 None；保留 sessions、selected_source、media、timeline、playback 和原始 ISO 时间。
- `last_error`：原生错误、格式错误、超时或监听器异常；正常新快照会清除之前的读取错误。
- `diagnostics`：独立持续排空 stderr 的有界记录（最近 50 条），与 stdout JSON 不混合。
- `is_running`：监控线程是否存活。`start()` 可重复调用而不重复启动进程；`stop()` 可重复调用；停止后可再次 start。
- `playback_state_from_snapshot(snapshot)`：独立纯转换函数。标题、艺术家、专辑按原样传递。位置和时长以 StartTime 为原点，已知 EndTime 时作边界裁剪，不拆解 Artist 字符串。

此 JSON-lines 是 bridge 内部数据格式；它不是 `docs/IPC_PROTOCOL.md` 的公共 IPC envelope。现有公共 IPC 和 PlaybackState 无变更。负责人仍负责 windows_smtc.py、live_overlay.py 和 CLI 的整合；本任务没有改动这些入口。

## 会话选择、错误及新鲜度规则

1. 每轮重新枚举会话。只接受实测 AUMID `AppleInc.AppleMusicWin_nzyj5cx40ttqa!App`，忽略大小写；不通过窗口标题或“Apple”子串猜测来源。
2. 系统当前播放器若是其他应用，仍选择列表中的 Apple 会话；其他应用只列出来源标识，不读取其媒体元数据。
3. 没有 Apple 会话时输出 `status="disconnected"`、`reason="apple_music_session_not_found"`，selected_source/media/timeline/playback 均为 null。Python 发布空的非播放 PlaybackState，不沿用其他播放器或之前歌曲。
4. WinRT 读取错误写 stderr JSON error，并在 stdout 发 `status="error"` 快照。连续模式会在下一轮重新请求 manager；单次诊断退出码 1。Python 对 error 帧清空发布状态。
5. LastUpdatedTime 是源时间轴更新时间，observed_at 是桥接采样时间。二者语义不同。当前适配器完全不根据 LastUpdatedTime、PlaybackRate 或墙上时间外推位置；即使旧时间轴持续报告 Playing，也只发布原始 Position。
6. Python 另外检查 observed_at 的新鲜度：超过 read_timeout 的旧帧或超过本机当前时间 5 秒的未来帧被拒绝。此检查不把旧 LastUpdatedTime 自动认定为断线。
7. 线格式为 UTF-8 无 BOM、一行一条 JSON；原生直接调用 Console.Out.WriteLine 和 Flush。stdout 行上限 65536 bytes；无换行的截断行、非法 UTF-8、错误协议版本及非 Apple connected 帧被拒绝。
8. 默认 poll_interval_ms=500、async_timeout_ms=5000、read_timeout=15 s、stop_timeout=2 s。每个异步 WinRT 调用独立限时，超时会尝试 Cancel；后台 Python 对无帧进程另设超时。全新有效 error 快照仍证明 bridge 存活，但不会保留旧播放状态。
9. stop 设置取消事件，终止并等待自己拥有的 PowerShell 子进程，超时再 kill 并等待；读取线程随后释放管道。启动后台线程失败时也回收已经创建的子进程。不存在脱离管理的辅助服务。
10. inspect_sessions 的 timeout 是查询期限，超时后会执行额外的有限回收等待（terminate/kill 各最多 2 秒），而不是留下超时进程。一次诊断错误通过 TimeoutError 或 SmtcBridgeError 报告。
11. 子进程使用 -NoProfile、-NonInteractive、CREATE_NO_WINDOW。-ExecutionPolicy Bypass 仅作用于这个子进程，未写入执行策略或其他全局配置。

## 已知限制和后续检查

- observed：当前包版本和这一次本机会话可用。unknown：其他 Apple Music 版本、其他 AUMID、真实同时存在多个 Apple 会话时的对象选择细节。
- observed：播放样本以秒为单位更新；暂停样本位置固定。unknown：真实拖动进度、手动切歌、客户端关闭/重启、会话消失/重现的完整链路。本任务遵照只读要求，没有主动触发这些行为。
- 无 Apple/多播放器选择有原生函数夹具验证，但没有为了验证而关闭播放器或启动其他播放器。
- Artist 包含合并文本、AlbumTitle 为空，可能影响歌词来源的精确匹配；需要上层用独立证据解决，bridge 不做猜测拆分。
- 回调在监控线程执行且应及时返回；UI 应通过已有线程安全队列接收。阻塞的用户回调无法被 Python 强行取消，可能延迟线程退出；stop 仍会回收其 PowerShell 子进程。
- 正常原生读取错误由脚本重试；整个 bridge 进程终止或协议/无帧超时后，监控结束并清空状态，需要调用方决定何时再次 start。
- 使用只读轮询，尚未接入 WinRT 事件；不平滑播放位置，不提供亚秒时间精度保证，不提取歌词文本。
- 安装打包时需包含 `src/amlyrics/bridge/smtc.ps1`。当前仓库直接从 src 运行已经验证，未安装或验证分发包。
- 原有 windows_smtc.py 能力边界保留，统一入口和发布流程由负责人整合。此记录可独立复核，不依赖 UIA agent 的进展。
