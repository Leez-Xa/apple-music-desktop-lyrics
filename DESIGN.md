# Desktop Lyric Design

Native WPF floating overlay window (`AllowsTransparency = true`, `WindowStyle.None`, `Topmost = true`, `SizeToContent.Height`, `ResizeMode.NoResize`).

- **Typography & Rendering**: Dynamic two-track or compact three-track layout (`LyricsLinePresenter`) using `Segoe UI` / `Microsoft YaHei UI` fallback, ink role `#F4F4F5`, subdued secondary alpha, and single-geometry vector stroke + drop shadow (`LyricsLineLayoutEngine.MeasureVertical` snaps glyph, outline, and shadow bounds to physical pixels without `ScrollViewer`s). When `ShowTranslation` and/or `ShowRomanization` are enabled via `LyricsTrackResolver`, 2-track mode shows Original + Next Original (default), Original + Translation, or Original + Romanization; when both are enabled and present, compact 3-track mode shows Original + Romanization + Translation and relaxes maximum height to 340 DIP. Long lines preserve the user's requested font size without shrinking and scroll horizontally via marquee (or ellipsize when animation is disabled); secondary tracks floor at 14 DIP so hierarchy holds even at minimum primary font size 20 DIP.
- **Bounds, Vertical Font Scaling & Top-Edge Alignment**: Allowed width 420–1400 DIP (default 760 DIP), primary font size 20–60 DIP (default 30 DIP), auto-calculated height clamped to 64–260 DIP in 2-track mode (up to 340 DIP in compact 3-track mode) and constrained to `SystemParameters.WorkArea`. Dragging the left/right edges changes only window width (and left position) without altering font size, whereas dragging the top/bottom edges (`Cursors.SizeNS`) proportionally scales `FontSize` within 20–60 DIP, lets `SizeToContent.Height` update the vertical box height automatically while anchoring the opposite edge, and keeps width fixed. When docked at the work-area top edge, `AlignInkToTop` keeps first-line ink ~1 device pixel below the top edge without clipping.
- **Hover / Keyboard Chrome**: Idle window background is fully transparent (`BackgroundOpacity` defaults to 0). When unlocked, pointer hover (`LyricsOverlayHover`, with `DWMWA_CLOAKED` cross-virtual-desktop suppression) or keyboard focus (`IsKeyboardFocusWithin`) reveals the translucent rounded backdrop and a detached centered `Popup` toolbar with 3 controls (`⚙`, `🔒`, `×`) placed above the overlay (flipping below when top-docked) without shifting lyric layout; resizing via any of the four edges keeps the translucent backdrop frame visible (while suppressing the hover toolbar) so the user can see the exact overlay bounds. Opening the settings panel keeps both the translucent backdrop frame and the detached toolbar controls visible (clicking `⚙` again toggles settings closed) while the settings popup opens outside both the lyric box and any same-side toolbar.
- **Click-Through Lock & Unlock**: Locking closes settings, hides the main frame/toolbar, disables edge resize handles, and enables true native mouse click-through on the main lyric window (`LyricsHitTestBridge` via `WS_EX_TRANSPARENT` and `WM_NCHITTEST -> HTTRANSPARENT`). Hovering a locked overlay reveals a clickable `🔓` button inside the detached `Popup` above/below the overlay; unlocking is also available from the system tray menu (`锁定/解锁歌词`) and `Ctrl+Alt+Shift+L`. Global hotkey registration failures are surfaced in the settings detail area.
- **Settings Panel**: Fixed `432×472` `Popup + TabControl` (`LyricsSettingsPanel`, anchored to `contentRoot` via `PlacementMode.Custom` with an 8 DIP gap plus same-side `ToolbarSurface` clearance—opening horizontally centered below the lyric window by default, automatically flipping above when bottom screen work-area space is insufficient, and dynamically repositioning on `SizeChanged`/`LocationChanged`) grouped into `显示`, `歌词`, and `同步`, with independent foreground and stroke color swatches, editable HEX inputs, custom WPF `LyricsColorPickerDialog` (2D SV + Hue bar, HEX/RGB inputs, 32 basic swatches, and 16 persistent custom palette slots with explicit slot selection, 2px black selection frame, automatic advance to the first empty slot, clear-slot support, and save-on-cancel behavior for `CustomColors`), current song timing status display (hiding the internal `1.5s` default lead and showing `0.0 秒` relative default, `±0.1s` / `±0.5s` buttons, and `±15.0s` per-song range without keyboard timing hotkeys), retry / `换一版歌词` (LRCLIB multi-candidate version cycling, capped at top 3 distinct synced candidates prioritizing fractional timestamps, excluding canonical-fingerprint duplicates and short stubs, honestly returning fewer than 3 without padding, with early-stop Traditional search) / local-import actions, and interactive `显示翻译` / `显示音译` checkboxes with live availability status (`ShowTranslation`, `ShowRomanization`).
- **Native Apple Music Lyrics Hybrid Fusion**: Read-only background UIA reader (`AppleMusicNativeLyricsService`) inspects uncloaked `AppleMusic.exe` windows (`TimeBasedLyrics` container), strips WinUI ruby format markers (`U+2060` Word Joiner / `U+00A0` NBSP), extracts original lines and `TranslationContainer`, generates Revised Romanization for Korean Hangul lines (`KoreanRomanizer`) when Windows UIA omits custom-drawn syllable romanization, performs both same-script and cross-script (Romanized LRCLIB ↔ Hangul Apple Music) alignment (`NativeLyricsAligner`), and caches enriched documents per track across virtual-desktop switches (when WinUI 3 hides XAML subtrees behind `DWMWA_CLOAKED`; invalidated cleanly when switching LRCLIB candidate versions). Live UIA viewport tracking also serves as fallback when synced LRCLIB lyrics are unavailable or unaligned while translation/romanization is requested. `LrcParser` requires consistent multi-line groups before classifying an LRC as bilingual/trilingual.
- **Persistence**: Atomic write-through JSON storage (`LyricsPreferencesStore`) to shared `work/state/settings.json` persisting window geometry (`Left`, `Top`, `Width`), lock state, appearance settings (including `ShowTranslation`, `ShowRomanization`, and `CustomColors`), per-song timing offsets (`1.5s` internal default lead, `±0.1s`/`±0.5s` UI steps, `±15.0s` relative bounds), and per-song preferred LRCLIB record IDs (`PreferredLrclibIds`). Manual startup forces visibility (`Enabled = true`) on launch without overwriting corrupt configuration files.
- **Standby & On-Demand Lifecycle**: A lightweight system-library-only watcher (`AppleMusicLyricsWatch.exe`, launched via `AppleMusicLyricsStandby.exe` or `scripts/StartStandby.ps1`) monitors `AppleMusic.exe` without loading WPF or PowerShell. When `AppleMusic.exe` starts, it launches `AppleMusicLyrics.exe --auto-launch` honoring the saved `Enabled` flag (showing immediately when `Enabled = true`, or staying hidden with tray, hotkeys, and user-SID-scoped Named Pipe IPC `HostIpc` ready when `Enabled = false`). Hiding the overlay stops the `DispatchTimer`, clears cached track state, and terminates `MediaSession.ps1` (`IMediaSourceLifecycle` + `ProcessJobGuard` kill-on-close Win32 Job Object). When all `AppleMusic.exe` processes exit, the watcher sends `CLIENT_EXITED` after debounce so the host cleanly exits back to standby while preserving `Enabled`. Upgrading via `ManageStandby.ps1 -Action Install` passes `--stop --include-host` to stop any older standby watcher and host cleanly before starting the new build launcher.
