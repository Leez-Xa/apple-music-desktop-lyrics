# Apple Music 内部按钮原型（2026-11-05）

当前实现由一个隐藏宿主同时管理内部原生按钮、SMTC、Apple 歌词文本读取和置顶歌词窗。运行时已对本机 Apple Music 包 1.1792.39682.0 / 文件 1.7.0.155 验证；没有改安装目录或注入 DLL。正式安装、自启动和签名尚未完成。

## 本次如何使用

本轮已启动默认离线的隐藏宿主。回到 Apple Music 所在桌面，在播放器顶部“重复”与歌曲信息区之间点击 **桌面歌词**。按钮来自独立进程自有的原生子窗口，父窗口为 Apple Music；没有单独控制面板。

悬浮窗支持拖动、字号、隐藏、退出。同一个内部按钮可再次打开/隐藏歌词窗。关闭 Apple Music 后，宿主在检测到主窗口消失持续 10 秒后退出；退出歌词窗也会移除按钮并回收辅助进程。

初次需要外部时间轴时，点击歌词窗中的 **启用在线同步**，阅读并确认授权。默认不请求外部歌词；确认仅对本次宿主运行有效，不改全局配置。若不授权，保持本地读取，缺少可核验时间轴时显示“暂无同步歌词”。

## Apple 歌词与同步的真实边界

Apple 自带歌词面板已打开且能够读取。跨虚拟桌面从主 HWND 有时只返回外壳；通过已核对 PID/包版本的 XAML 内容子 HWND，可继续读取播放器和 TimeBasedLyrics。

实测读到《天黑黑》的 38 个歌词行，连续 58/59/60 秒采样中面板滚动位置变化。行控件只暴露 Invoke/ScrollItem 等接口，当前已探测属性没有行时间戳或选中标记。把“看得到高亮”与“接口可返回高亮”分开记录，不按列表索引、居中位置或观察时刻编造歌曲时间轴。

另一虚拟桌面上的图像捕获返回空白，本轮没有把它作为可用高亮识别源；也没有为了取图切换桌面或激活 Apple Music。

歌词管线顺序：Apple 原始同步结果接口 → 显式外部同步歌词回退。当前 Apple 原始时标不可得；若外部时间轴与 Apple 完整非空文本序列逐行一致，则使用 Apple 文字和外部时间，来源明确为 apple_music+external_timing；否则使用已严格匹配的外部同步歌词。文字不同或无时标都不伪造成 Apple 原始同步歌词。

## 外部来源

官方 docs.md 已只读核对 /api/search 的 track_name 参数和数组返回。搜索仅发送曲名，候选在本机重建“artistName — albumName”，与 SMTC 原始副标题精确比较，再检查标题、版本、时长和同步歌词。不会猜拆或修改原始 Artist；匹配多个候选时拒绝。

仍保留普通元数据 /api/get 路径；该路径会发送曲名、艺术家、专辑和时长。两条路径都受到 enable_external 和本次 allow_network 双开关限制，有超时、响应上限、缓存、404/429 诊断。本轮工具没有请求真实歌词 API；在线端到端效果待用户在窗内明确授权后验证。

## 开发运行入口

本机已有 Python 3.13.1、Tkinter、系统 Windows PowerShell 5.1。生产路径使用标准库与系统组件，不需要新增依赖。Pillow 只用于已有环境中的研究截图，不是运行依赖。

```powershell
python scripts/run_integrated.py
# 有限时、不弹歌词窗的运行检查
python scripts/run_integrated.py --duration-seconds 4
# 实际挂接检查，仅点击本程序自己新建的按钮，强制禁止显示悬浮窗
python scripts/verify_apple_attachment.py
```

正式以隐藏方式启动可用本机 pythonw.exe 执行该入口。本次已代为启动，不必再次运行；命名互斥锁限制为一个宿主。

## 验证与兼容性

- compileall 成功；219 项测试，217 通过、2 跳过。跳过项为系统不登记从未显示的隐藏窗口的虚拟桌面 ID，未记作成功移动。
- 实际 Apple 父子 HWND 链、按钮 PID 属于宿主、点击回调、隐藏歌词窗、退出清理全部通过。
- 实挂测试前后前台 HWND 不变，Apple 仍在另一虚拟桌面；没有桌面切换或用户窗口移动。
- 按钮只占用已测得 RepeatButton 与 LCD 间的空隙；空间不足、版本不符、快照过期、窗口移动或缩放后布局过时，均撤下按钮等待新证据。
- 自有子窗口在本线程临时匹配父窗 DPI；不改变进程/系统默认，不使用 SetParent 或子类化 Apple 的窗口。
- 前台 Apple 的用户点击才能显示悬浮窗；后台测试只验证回调，不弹窗。Shell 不登记边框工具窗的桌面 ID，因此生产点击路径不使用虚拟桌面移动接口。
- 尚未验证其他客户端版本、真实多 DPI 布局矩阵、实际鼠标点击后的可见悬浮窗、用户授权后的真实外部歌词匹配，以及签名安装/重启自动接入。

研究总记录见 docs/research/apple-music-runtime.md。按钮实挂证据见 research/apple-music/evidence/native-apple-attachment-20261105-193747-831863.json。


## 最新修正：可见层与诊断

上文 WS_CHILD 子窗口方案已被用户实际截图证明不能保证显示，当前使用只覆盖同一顶部空隙的自有贴附按钮层（owned popup），不是 Apple 进程内 XAML 控件。它随 Apple 的几何和虚拟桌面状态变化，处于 owner 上方、遮挡应用之下，不激活或切换桌面。旧“句柄存在/模拟点击成功”不再作为可见性通过证据。

黑色/白色或近常量截图现在一律拒绝，旧全黑截图的成功记录已在研究总记录中撤回。当前全项目 241 项，239 通过、2 跳过。

歌词窗现直接提示未开启在线同步、查询超时、连接失败或歌曲版本无匹配；日志记录查询结果、耗时和退出原因。在线确认仍按界面提示仅对一次宿主运行有效，重启默认离线。
